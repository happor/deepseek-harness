# Distribution
How a profile becomes a running application: the ordered bundle layers a profile stacks, the boot glue that resolves and mounts them, and the CLI, Desktop, SDK, and ACP entrypoints that deliver the result. This is a **process context, not a [seam](../../glossary.md#capability-seam)** — it owns no capability that another context swaps, only the path from a profile on disk to a running process, so its vocabulary is about starting an application rather than about what the application can do.

Members: `apps/cli`, `apps/desktop`, `apps/desktop-host`, `apps/plugin-market-generator`; `packages/boot` (6), `packages/bundle` (6), `packages/sdk` (3), `packages/acp` (1) — 16.

`experimental/` `plugin-market-bundle` is filed here by subject: an optional bundle that mounts custom plugin indexes — the Host `pluginMarket` service and the Web Discover tab of the Plugins page.

## Language

### Composition

**profile**: A named composition on disk, stored under the [harness home](../platform/GLOSSARY.md): it lists the bundles it stacks, holds the out-of-tree plugins it installs, and keeps its own user patch file. A profile is the thing a launcher boots, and the shipped ones each begin as a template. _Lives in_: `packages/boot/app-boot` ([Profiles](../../../packages/boot/app-boot/README.md#profiles)) · [architecture.md](../../architecture.md) (§Profiles and bundles) · [apps/cli/README.md](../../../apps/cli/README.md#profiles). _Avoid_: workspace, config, environment.

**bundle**: A package that ships a Cordis config patch together with the code its rows mount, declaring in its own manifest which patch file it contributes so later layers can still patch what it inserts. A bundle is a distribution format for rows, not an entry in the tree it contributes to. _Lives in_: `packages/bundle` ([README](../../../packages/bundle/README.md)) · [architecture.md](../../architecture.md) (§Profiles and bundles). _Avoid_: plugin pack, extension package, patch package.

**patch layer**: One ordered round of patch operations applied over an empty root; the layers are the profile's bundles in order, then the profile's own patch file, then the home-level patch, then any command-line layers, and a later layer wins per row. A patch replaces a targeted row's whole configuration rather than merging keys, and may insert new rows. _Lives in_: [apps/cli/reference/README.md](../../../apps/cli/reference/README.md#profile-boot) (§Profile boot) · `packages/boot/app-boot` ([Profiles](../../../packages/boot/app-boot/README.md#profiles)). _Avoid_: override, overlay, merge.

**composition**: The complete entry tree a profile resolves to once every patch layer has applied — what boots, what the dump commands print, and what a reconciliation reapplies. It is the unit of inspection and of change: a plugin operation or a patch edit is a change to a composition. _Lives in_: [architecture.md](../../architecture.md) (§Profiles and bundles) · [apps/cli/composition.md](../../../apps/cli/composition.md). _Avoid_: config tree, plugin graph, entry list.

**shipped template**: One of the five profiles the installation itself ships as a starting point (`web`, `headless`, `sdk`, `sdk-minimal`, `acp`), from which a profile of that name initializes itself on first use. Replacing a custom profile with a fresh copy of a template copies its bundle list alone, never another profile's dependencies or patches. _Lives in_: [apps/cli/reference/README.md](../../../apps/cli/reference/README.md#profile-boot) (§Profile boot) · `packages/boot/app-boot` ([Profiles](../../../packages/boot/app-boot/README.md#profiles)). _Avoid_: default profile, preset, scaffold.

**base bundle**: The shared first layer of the base-backed profiles: model adapters, tools, persistence, sandbox and approval policy, settings, credentials, and telemetry. Every other shipped bundle patches over it instead of restating it. _Lives in_: `packages/bundle/base` ([README](../../../packages/bundle/base/README.md)) · [architecture.md](../../architecture.md) (§Profiles and bundles). _Avoid_: core bundle, common bundle.

**mode bundle**: A bundle that adds the rows of one shipped application over the base bundle — the browser application, the one-shot runner, the SDK server, or the ACP server. Mode bundles are what make the shipped profiles differ from each other; `sdk-minimal` is the deliberate exception that carries its whole tree in one bundle. _Lives in_: [apps/cli/composition.md](../../../apps/cli/composition.md) · `packages/bundle` ([README](../../../packages/bundle/README.md)). _Avoid_: app bundle, surface layer.

**runtime resolution**: The immutable package-location table computed at launch from the installation and the ordered bundle dependency graphs, which decides which copy of every package the composition runs. It is computed once from an installation-first, ordered-bundle traversal, and startup creates no links or fallback copies. _Lives in_: `packages/boot/app-boot` ([Profiles](../../../packages/boot/app-boot/README.md#profiles)) · [apps/cli/reference/README.md](../../../apps/cli/reference/README.md#profile-boot) (§Profile boot). _Avoid_: module map, resolution cache, fallback links.

**exact-version exemption**: A saved grant that lets one exact plugin version run on named exact runtime versions despite its declared compatibility range, recorded beside the profile rather than in its manifest. Neither a plugin upgrade nor a runtime upgrade inherits a grant, so each incompatible pair is accepted on its own. _Lives in_: `packages/boot/app-boot` ([Profiles](../../../packages/boot/app-boot/README.md#profiles)) · `packages/boot/plugin-manager` ([plugin-manager](../../../packages/boot/plugin-manager/README.md)). _Avoid_: allowlist, compatibility override, force flag.

**required entry**: A composition entry whose failure to activate stops startup: the launcher disposes the whole tree and exits nonzero. Every other entry is optional, so its failure is a labelled warning and the rest of the application keeps running. _Lives in_: `packages/boot/app-boot` ([Startup and reload failures](../../../packages/boot/app-boot/README.md#startup-and-reload-failures)). _Avoid_: critical plugin, mandatory plugin.

**boot**: The launcher's act of turning a profile on disk into a running application: load the environment layers, compose the patch layers, resolve packages, mount every row, and judge which failures stop startup. Boot glue is the boot group's own name for the shared library behind every profile, including the Desktop Host's. _Lives in_: `packages/boot` ([README](../../../packages/boot/README.md)) · `packages/boot/app-boot` ([README](../../../packages/boot/app-boot/README.md)). _Avoid_: startup, page boot.

### Launch and entrypoints

**launcher**: The `dsh` command, the sole supported way to start a Node Harness application: it parses only its own flags and selects a profile by name. Each shipped application is a profile rather than a separate executable, so the SDK and ACP products are served by this same launcher. _Lives in_: `apps/cli` ([README](../../../apps/cli/README.md)) · [architecture.md](../../architecture.md) (§Application launch) · [docs/cli-help.md](../../cli-help.md). _Avoid_: bin, wrapper, shell wrapper.

**app arguments**: Everything after the first token the launcher does not recognize, handed to the booted profile verbatim so the application's own plugins parse it. Launcher flags therefore end where app arguments begin, and `--help` means whichever side owns it. _Lives in_: [apps/cli/reference/README.md](../../../apps/cli/reference/README.md#app-arguments) (§App arguments) · `packages/boot/cmdline` ([README](../../../packages/boot/cmdline/README.md)). _Avoid_: passthrough flags, extra args.

**headless task**: The one-shot mode of a profile: a single task is answered in one fresh persisted session and only the final assistant text is printed before the process exits, with the exit status reporting the outcome. The shipped headless profile mounts no browser connection, HTTP server, or listening port. _Lives in_: `packages/bundle/headless` ([README](../../../packages/bundle/headless/README.md)) · [apps/cli/reference/README.md](../../../apps/cli/reference/README.md#profile-boot) (§Profile boot). _Avoid_: batch job, CLI mode, script.

**Desktop Host**: The private host process the desktop application starts in Node mode, which runs the shared profile lifecycle and the complete Web application behind the window. It owns the desktop profile and its package state, while the shell owns only the window, the assets, and the native surface. _Lives in_: `apps/desktop-host` · [apps/desktop/README.md](../../../apps/desktop/README.md#installation-ownership) (§Installation ownership) · [architecture.md](../../architecture.md) (§Desktop application). _Avoid_: desktop server, sidecar, backend.

**desktop application**: The Electron shell that wraps the complete Web application in a native window and owns the reserved `desktop` profile, which the CLI refuses to boot. The shell's job is delivery: it starts the Desktop Host, serves the packaged Web assets locally, and forwards authenticated requests and window lifecycle to it. _Lives in_: `apps/desktop` ([README](../../../apps/desktop/README.md#application-overview)) · [architecture.md](../../architecture.md) (§Desktop application). _Avoid_: desktop client, native app, GUI shell.

**boot injection**: A value the Desktop Host supplies to the packaged Web page before that page starts its client — readiness, fatal startup reports, native path references — which the loading page waits for instead of navigating to another document. Injections travel on a private channel between the shell and the Host, not through the page's own storage. _Lives in_: [apps/desktop/README.md](../../../apps/desktop/README.md#application-overview) · [architecture.md](../../architecture.md) (§Desktop application). _Avoid_: bootstrap data, hydrate payload, preload state.

**SDK server**: The stdio server the SDK profile mounts, serving out-of-process SDK clients over newline-delimited JSON-RPC so another process can open sessions, send prompts, and observe events. The SDK is a profile plus a wire protocol, not a separate application and not a project scaffold. _Lives in_: `packages/sdk` ([README](../../../packages/sdk/README.md)) · `packages/bundle/sdk-app` ([README](../../../packages/bundle/sdk-app/README.md)). _Avoid_: SDK API, client library, RPC framework.

**ACP server**: The automation-only server the ACP profile mounts, exposing persistent agents to programmatic clients over the Agent Client Protocol on stdio. It is the automation entrypoint rather than a human one, so no browser or window surface is mounted beside it. _Lives in_: `packages/acp` ([README](../../../packages/acp/README.md)) · `packages/bundle/acp-app` ([README](../../../packages/bundle/acp-app/README.md)). _Avoid_: ACP bridge, automation plugin.

## Defined elsewhere

- **seam** — defined once in the [root glossary](../../glossary.md#capability-seam); this context has no seam of its own, so the word appears here only to say what distribution is not.
- **harness home** — the user-data root that profiles live under is defined in the [platform glossary](../platform/GLOSSARY.md); distribution only names profiles inside it.
- **page boot / boot graph** — the browser's module-level boot belongs to `web-gui` ([glossary](../web-gui/GLOSSARY.md)); "boot" here is always application boot.
- **session** — the durable unit a headless task or an SDK or ACP client creates belongs to `session-data` ([glossary](../session-data/GLOSSARY.md)); distribution starts the process and then steps out of the way.
